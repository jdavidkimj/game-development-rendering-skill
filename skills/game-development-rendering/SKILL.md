# Game Development & Rendering

Build the intended experience in the running game. Preserve selected designs and working systems, diagnose the cause of a mismatch, and demonstrate the changed behavior. Convincing quality comes from construction, surface response, motion and interaction at the gameplay camera; more polygons or glow alone do not establish improvement.

- For reference matching, modeling, rigs, UVs, materials, baking or terrain, read [visual production](references/visual-production.md).
- For consistent references and character inspection across angles, read [multi-view review](references/multi-view-review.md).
- For lighting, effects, gameplay feel, integration or performance, read [runtime verification](references/runtime-verification.md).

## Establish the target and evidence

When a multi-view reference workflow has been agreed, reference readiness is a prerequisite to geometry work. Verify the required reference views exist and have been inspected for consistency with the selected design and later corrections before modeling or delegating it. Model screenshots do not satisfy this prerequisite. Keep reference readiness, model review and user approval separate; use the project's preflight when available.

Read the project's current instructions, resume and relevant open feedback. Identify the active asset, exact runtime, selected reference, baseline and requested difference. An approved reference and subsequent explicit corrections define the target. Keep local preferences and proprietary evidence in project-owned records.

Translate feedback into observable criteria: which shape, material response, light source, timing, contact, motion or action cue must change, and under which conditions? Distinguish presentation defects from simulation defects. Do not silently alter collision, range, damage or timing to make a visual fit.

Use the smallest representative experiment that resolves uncertainty. Compare retained baseline and candidate with matched execution mode, camera, pose/time, scene, exposure and settings. Record exact source/asset identities or hashes. Label deliberate camera or lighting studies separately. Inspect actual output before expanding the method.

Choose evidence that supports the claim. Stills establish momentary appearance; sampled poses establish those deformations; continuous normal-speed footage supports motion quality; instrumentation establishes measured state; tests establish their assertions. No single form proves the whole experience. Respect requested review stages while recording later integration or motion work as pending.

Keep technical success, observed improvement, user acceptance and publication separate. A concept image is not an engine capture, and a preview scene is not a representative crowded battle. State practical limits and remaining gaps.

## Learn without expanding scope

Record feedback and verified results in the project's existing canonical learning records. User silence is not approval. When repeated cosmetic attempts fail, obtain new causal evidence about geometry, bind space, material channels, event timing or frame delivery before another tweak.

At the end of a useful batch, update the narrowest lesson that changes the next decision. Replace or qualify failed guidance and preserve counterexamples. Promote methods within their demonstrated scope. File-based learning improves the workflow; it does not retrain the model or imply background monitoring.

This skill guides authorized work. It does not itself authorize publication, unrelated downloads or installations, purchases, new chats, schedules, deletion of retained work or unrelated product changes.
